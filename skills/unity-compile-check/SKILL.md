# Unity 编译核对

先确认目标工程、ProjectVersion.txt、项目声明的编译入口、目标平台和本次受影响程序集。路径和版本从当前环境取得，不继承其他工程的机器表。

目标工程已在 Editor 打开时使用项目可用的编译接口，确认本次刷新、编译及需要的 Domain Reload 已结束，再读相关新错误。Editor 与运行时程序集都需覆盖；旧程序集上的测试不能代替本次编译。

未占用工程可用匹配版本 Unity 的批处理编译流程，使用本次独立日志并检查进程退出、编译完成及错误；具体参数查当前项目或安装版本文档。不要为验证关闭用户编辑器或擅自升级工程。

`dotnet build` 可作辅助，先确认 csproj 包含改动文件及所需宏；索引可能过期，结果不能直接替代 Unity 编译。没有 sln 不等于只能静态检查。条件编译按真实目标配置验证，不默认向业务代码插入故意错误。

不要批量替换中文标点、字符串插值或编码；只在语法上下文与编译证据表明有问题时修正。错误归属结合差异和调用关系判断，仅因文件未改过不能断定错误早已存在。依赖、程序集、导入和构建失败也要报告，不只过滤 CS 错误。

修复本次引入问题后再验证；重复失败改用新证据定位，不机械限定修复次数。报告实际覆盖、结果及受阻部分，不把无新日志当成功。
