# 通用设计与交付约定

本文件提供跨项目默认做法。具体项目的技术栈、授权、产品决定和验收基准由该项目规则明确；有不适用处说明差异，按当前任务处理，不因此自动重构已有成果。

- 常用调整提供容易找到的入口，字段和说明面向使用者，必要时注明单位。配置跟随业务归属；资源配置位置、实例挂载位置和生命周期管理者可以不同，但应能说明。
- 静态美术与动画资产保留编辑控制权，代码负责动态行为；不得为绕过资产问题持续覆盖静态参数。同一属性避免多处争用。
- 模块说明职责、输入输出和生命周期，通过稳定接口接入。对象创建、更新、取消与释放有明确归属，异步回调失效和动作中断要有处理路径。
- 生成工具保护已有可编辑成果；正式资源缺失明确报出，必要的原型或测试回退与正式路径区分。
- 按实际需求提取复用；不为假想需求增加框架。可复用模块在现有接口或模块文档中补齐适用范围、最小调用方式、调整入口和生命周期，不要求额外重复成文。
- 验证范围跟随改动影响。编译、逻辑、真实交互和画面各证明不同事情；只报告本次实际结果，历史通过与实例生成不代表当前功能或画面已验收。
- 交付说明结果、使用或调整入口、实际验证和剩余限制，篇幅随任务复杂度决定。重复失败时用新证据调整方法，不按修改次数机械扩大重构。

## 产品立项与共用模块接入

产品立项或首次规划架构时，检查 UI_Manager 与 Level Difficulty Tool 的适用性，读取对应模块的当前接入入口，提前安排 UI 生命周期、产品业务适配与难度评估接口。默认纳入产品接入计划；不适用或暂缓时在项目模块文档说明原因与接入时机，不要求立项当天全部实现。

模块文档由各模块维护源负责，本共享仓库只维护读取入口与时机，不复制整套接口规则：

| 模块 | 在模块维护源中读取 | 关注点 |
|---|---|---|
| UI_Manager | `README.md` → `UnityProject/Assets/UI_Manager/Docs/接口文档-接入指南.md`；接口细节查同目录 `接口文档-总览.md` | 框架与业务职责、模板落地、窗口生命周期、产品资产保护 |
| Level Difficulty Tool（当前公共包为 ipu_workflow） | `README.md` → `ipu_workflow/WORKFLOW.md`；API 与依赖查 `ipu_workflow/README.md` | 项目提供模拟与生成适配，公共模块负责评估工作流；候选生成与正式回填的边界 |

项目入口记录模块来源位置和本项目文档链接；现有模块文档记录实际采用版本或文件摘要、接入状态、必要定制及待验证项。沿用已有条目，不额外要求一份立项报告。上游版本不等于项目采用版本。

首次接入读取接入指南；升级读取目标版本说明并核对本地定制；日常修改只读相关接口。普通任务不重复通读、不自动更新模块。同步共享规则只更新规则和 Skill，不下载或升级这两个模块的代码。

来源未配置或文档不可访问时说明缺项，继续独立工作，依赖该接口的部分待核对后实施；不猜测仓库地址，不把本机目录当成其他电脑都存在的路径。

## 本地工具交付

后续交付面向使用者的工具，在项目根目录 `tool/` 集中提供易辨认的启动入口。Windows 工具提供双击 BAT；HTML 需要本地服务时，由入口启动服务并在就绪后打开浏览器，重复启动尽量复用本项目服务。启动不自动执行生成、发布等业务动作。

入口相对项目定位，失败保留可操作说明，交代如何停止服务。源码沿用合理位置，无需为统一入口迁移旧文件；一次性取证产物不必包装成长用工具。本约定不要求主动批量改造旧工具或其他项目。
